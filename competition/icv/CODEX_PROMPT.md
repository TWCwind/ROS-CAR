# 给 Codex 的后续任务

我们参加 2027 年中国大学生工程实践与创新能力大赛的「虚拟仿真赛道—智能网联汽车设计」赛项。请在本仓库内推进参赛算法，先阅读 `AGENTS.md`、`competition/icv/README.md` 和 `competition/icv/path_tracking.py`。`path_tracking.py` 仅是从 `pb2025_sentry_nav` 的前视点选择逻辑改写的路径跟踪参考，尚未连接赛事平台。

1. 先取得并阅读赛事仿真平台的最新开发手册、API、示例程序、场景与评分规则；若本地或仓库里没有，先列出具体缺失项，并完成不依赖这些资料的工作。不要臆造传感器字段或控制协议。
2. 明确平台输入（车辆状态、道路/车道、信号灯、障碍物、传感器原始数据等）和输出（转向、油门、制动、挡位等）的实际格式、单位、坐标系和调用频率，写成简短接口说明。
3. 将参赛代码放在 `competition/icv/`，与现有 ROS 小车的人体跟随、语音、底盘启动链隔离。优先实现能在平台示例场景闭环运行的最小版本：状态读取 → 路径/目标生成 → 前视点选择 → 汽车转向与速度控制 → 命令输出。复用 `path_tracking.py` 时核对车体坐标系、轴距、转向限幅、路径排序和采样频率；必要时修改。该代码仅支持正向跟踪，倒车泊车另行设计。
4. 按赛事实际任务逐步补齐车道保持、紧急制动、信号灯响应、障碍物处理、自动泊车和连续场景。区分平台直接给出的真值与需要自行感知的量，避免重复开发。
5. 每完成一个场景，记录运行结果和评分、失败原因、改动前后对比；把尚未验证的功能明确标注。按仓库约定更新 `WORKLOG.md`。不要将仿真通过写成国赛虚实融合或实车验证。
6. 保留 `competition/icv/LICENSE` 和 README 中的原作者、来源与 Apache 2.0 说明。不要复制哨兵机器人的全向底盘控制、特定雷达驱动、地图或仿真配置到正式参赛入口，除非已证明赛事平台需要并完成适配。

请先给出基于实际平台资料的缺口清单，然后直接实现首个可运行的闭环版本，并说明运行方法与验证结果。
